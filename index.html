Separation the skill refuses to blur

Inspection

Static characteristics of a candidate: metadata, commands, network, license, risk score. Reduces risk; proves nothing.

Approval

The user's recorded consent to install, with the permissions that were shown at that moment.

Activation

The skill's instructions becoming available for one task. Grants no permissions at all.

Tool authorization

The permission engine's per-action decision at run time. The only thing that can allow an effect.

Free-first onboarding order

1 · Security & trust

Permission inspector, skill inspector/validator. Declining these never weakens the built-in safeguards — those live in code.

2 · Decision-making

Error diagnoser, planner & context recovery, resource-aware execution.

3 · Technical

Codebase explorer, test verifier, Git review, dependency/license audit, VSIX release.

Every candidate is shown as a card with purpose · source at a pinned ref · license · price model · permissions · risk · required/optional and [Inspect] [Install] [Skip]. "Free" means the licence permits the use — not merely "no card required today".

Install & invoke

# project skill (travels with the repo)
mkdir -p <your-extension-repo>/.cline/skills
cp -r .cline/skills/vibecode-engine-rebuild <your-extension-repo>/.cline/skills/

# then in VS Code: Settings → Features → Enable Skills
# Cline panel → Skills tab → "vibecode-engine-rebuild" · or /skills · or name it in the prompt

What is not done yet
